# TechPilot 架构说明

> 更新日期：2026-10-12
> 文档职责：说明当前已实现的 Runtime 边界和已确认的下一阶段方向。
> 施工顺序以 [开发路线](开发路线.md) 为准；完整方向以 [技术决策 Agent 方向收敛与实施路线](设计决策/技术决策Agent方向收敛与实施路线_2026-10-12.md) 为准。

## 1. 产品定位

TechPilot 是本地优先的技术协作 Agent。它以 Coding Agent Runtime 为底座，能够在真实仓库中理解任务、读取和修改代码、运行验证，并通过 Session、Permission、Tool effect 与执行控制保留可审查的执行边界。

当前产品入口是 `techpilot` 的普通 Chat 与 TUI。`/goal` 及其已有持久化能力保留，但 Goal / Long Task 的复杂恢复、重规划、租约和证据失效机制已冻结，不再作为近期主线。

下一阶段把产品重心扩展到“技术决策与技术选型 Agent”：先读取项目规则，再按专家视角和可复用方法分析问题，必要时通过受控外部工具收集资料，最终输出有约束、有取舍、有依据的推荐。

## 2. 当前执行链

```text
CLI / TUI
  -> RuntimeBootstrap
     -> Repository Profile + 项目上下文
     -> Agent
        -> Provider
        -> Tool Call 参数校验与准备
        -> ToolExecutionPlan
        -> Effect Journal
        -> RepositoryToolExecutor
           -> Execution Control
           -> Permission / Trusted Diff
           -> Tool
        -> ToolResult + Runtime Event + Session Event
```

模型只提出 Tool Call。Runtime 承担实际的参数校验、effect 分类、调度、路径边界、执行控制、权限确认和结果持久化；提示词、Role、Skill 或外部工具描述均不拥有执行权。

## 3. 已实现的核心能力

| 能力 | 当前事实 |
|---|---|
| Agent 与 Context | 单一 AgentLoop；系统上下文加可压缩的会话历史；上下文压缩不覆盖原始事实 |
| Session / Event | JSONL 追加式 Session 与 Runtime Event；恢复只重建对话投影，不重放历史副作用或授权 |
| Tool 安全 | 参数校验、仓库路径边界、敏感文件保护、Execution Control、Permission 与 Trusted Diff |
| 调度 | 资源明确的安全读取可并发；写入、执行、网络、委派、未知调用保持独占；事件和结果按模型调用顺序保存 |
| 副作用记录 | 非读取调用经 Effect Journal 记录；状态不明时保守停止，不自动重试 |
| Role / Skill 基础 | 已有 Role / Skill 契约、注册、版本、批准/撤销和 Runtime 激活基础；尚未完成产品级选择与技术选型 Skill 接入 |
| Research 基础 | 已有本地资料快照、证据引用、候选比较与报告校验；普通 Chat 与 Research Runtime 尚未合并 |
| Goal / Long Task | 已有 plan、task、checkpoint、effect journal、evaluation 等基础；近期冻结深度扩展 |
| 评测 | 冻结的 144 条 `core-v0` Runtime Replay 契约集；另有约 100 个私有模型任务 case，二者口径分离 |

## 4. 模块职责

| 模块 | 职责 |
|---|---|
| `techpilot/engine/agent.py` | 唯一 AgentLoop、Provider 调用与 Tool Call 轮次驱动 |
| `techpilot/engine/context.py` | 会话上下文估算、裁剪、摘要和硬收缩 |
| `techpilot/engine/tool_execution.py` | Tool effect、资源描述、并发波次与独占屏障 |
| `techpilot/runtime/bootstrap.py` | Runtime、Agent、Session、Permission、Effect Journal 的统一装配 |
| `techpilot/runtime/sessions.py` | Session JSONL、事件重放和模型消息投影 |
| `techpilot/runtime/effect_journal.py` | 非读取 Tool effect 的落盘、恢复核对和不确定状态处理 |
| `techpilot/runtime/extensions.py` | Role / Skill 契约、Registry、版本和激活校验 |
| `techpilot/chat/executor.py` | 仓库范围的 Tool 执行、路径规范化、执行控制与 Permission 接入 |
| `techpilot/chat/permissions.py` | Chat 的确定性权限策略和交互确认 |
| `techpilot/research/` | 资料快照、证据、比较报告和 Research Runtime |
| `techpilot/evaluation/` | 确定性 Replay、冻结基线和模型任务评测驱动 |

## 5. 近期扩展边界

后续按以下顺序推进：

1. 项目根 `AGENTS.md`，作为受限、稳定的项目 instructions；
2. Role，提供专家身份与分析视角；
3. `technology-selection` Skill，提供技术选型方法；
4. MCP，作为统一经过 Runtime 的外部资料 Tool；
5. 完整技术选型场景。

Role 只决定分析视角，Skill 只决定任务方法，MCP 只提供外部工具连接。三者都不能提升 Permission、改变 Tool effect、调整调度、恢复授权或创建第二套执行循环。

## 6. 不可破坏的边界

1. 所有 Tool（包括未来 MCP Tool）必须经过同一 Runtime、Execution Control、Permission 和 Effect Journal。
2. Tool 对模型可见不等于获准执行；Tool Schema、Skill 内容和远端 annotation 都不是授权事实。
3. `PreparedToolCall` 的已验证参数与调度事实必须用于实际执行；无效参数不能触发外部调用。
4. Raw Session / Event 是历史事实来源；模型上下文、Role、Skill 和压缩投影不能覆盖它。
5. Session 恢复不恢复历史授权，不重放 Tool 副作用，也不静默重新激活历史 Role。
6. 路径策略、敏感文件保护、Trusted Diff 和写入确认不因扩展而放宽。
7. 冻结评测 expected 与安全边界不得为提高通过率而修改。

## 7. 当前非目标

- 复杂 Memory、Vector DB、RAG；
- Goal / Long Task 深度扩展；
- 大规模架构重构；
- 通用 Skill 市场、自动发布或自动改写 active Skill；
- 多 Agent / 后台 Agent Team；
- MCP sampling、远端任务编排或绕过 Runtime 的执行路径。
