## 当前结论

TechPilot 已具备 Coding Agent Runtime 的核心基础：Session / Event 持久化、Context 管理与压缩、Tool 调用与权限控制、Tool effect 分类与调度、Role / Skill 基础契约，以及初步 Goal / Long Task。

近期主线是“技术决策与技术选型 Agent”。Goal / Long Task 保留为已实现能力，但冻结复杂 recovery、replan、lease、evidence invalidation 等深度扩展；除非新功能确实无法在现有边界内实现，不为它们做重构。

## 当前关卡：A1 项目级 AGENTS.md

目标是在普通 Chat 与 TUI 中加入轻量的仓库根 `AGENTS.md` 支持。

### 范围

- 只读取选定仓库根目录的一个 `AGENTS.md`；
- 通过 Runtime 基础系统上下文注入；
- 记录来源路径和内容摘要；
- 校验路径、文件大小与 UTF-8；缺失时正常继续，读取失败时明确提示；
- 启动和 Session 恢复时读取，单次运行内保持固定；
- 不实现父目录继承、嵌套覆盖、全局搜索、文件监听或额外依赖。

### 不可破坏的边界

`AGENTS.md` 只能提供项目 instructions。它不能授予 Permission、改变 Tool effect 或调度事实、自动执行命令，也不能覆盖 Runtime、Trusted Diff 或用户明确要求。

### 完成条件

1. 文本 Chat 与 TUI 使用同一份项目 instructions；
2. 缺失、越界、过大或无效编码的输入安全降级；
3. Session、Permission、Tool 列表、Context 压缩和恢复语义不变；
4. 新增少量定向 integration cases，通过既有 Runtime 回归。

## 后续顺序

| 阶段 | 内容 | 进入条件 |
|---|---|---|
| A2 | Role：`software-architect`、`ai-engineer` 等专家视角 | A1 已通过定向回归 |
| A3 | `technology-selection` Skill：约束、候选、证据、trade-off 与推荐流程 | Role 的产品接入稳定 |
| A4 | MCP：受控外部资料 Tool，统一经过 Runtime | Skill 可形成清晰的信息缺口 |
| A5 | 完整技术选型场景 | Role、Skill、MCP 的小规模集成用例通过 |

完整设计、责任边界、预计文件和验收规则见 [方向收敛与实施路线](设计决策/技术决策Agent方向收敛与实施路线_2026-10-12.md)。

## 固定 Runtime invariant

1. 所有 Tool（含未来 MCP Tool）经过同一 Runtime、Execution Control、Permission 和 Effect Journal；
2. Role、Skill、项目 instructions 和远端 Tool annotation 都不能提升权限或改变 effect；
3. 只有资源明确的安全读取可并发，网络、写入、执行、委派和未知调用保持独占；
4. Tool Result、Runtime Event 与 Session Tool 消息保持模型调用顺序；
5. Raw Session / Event 是事实来源，Context 与扩展提示词只是投影；
6. 恢复不恢复历史授权、不重放副作用、不静默重新激活 Role；
7. 不修改冻结 expected 或放宽安全边界来提高评测分数。

## 评测策略

- 约 100 个私有 Runtime 模型 case 继续冻结，作为模型行为 regression baseline；
- 144 条 `core-v0` Runtime Replay 契约集继续冻结，作为确定性 contract baseline；
- A1、Role、Skill、MCP 各自只增加少量针对性 integration cases；
- 最终重点评测技术决策场景的约束识别、候选覆盖、证据支持、trade-off、条件性推荐与未知项；
- Runtime baseline 与技术决策质量分开统计，不以单一分数混合表述。

## 暂不实施

- 复杂 Memory、Vector DB、RAG；
- Goal / Long Task 深度扩展；
- 大规模架构重构；
- 通用 Skill 市场、自动发布或自动修改 active Skill；
- 多 Agent / 后台 Agent Team；
- MCP sampling、远端 Agent 或远端任务编排。

## 开发规则

每个切片开始前，先确认输入、输出、事实保存位置、失败表示、取消与恢复语义、定向测试和对冻结基线的影响。

一个切片只解决一个边界问题；先跑相关测试，再跑必要的 Runtime 回归、Ruff 与 `git diff --check`。发现需要改变 Goal、Permission、Effect、Session 或调度语义时，先形成单独设计决定，不在功能切片中顺带重构。
