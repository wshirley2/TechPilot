# TechPilot 候选改进清单

> 更新日期：2026-10-12
> 本文只保存未排期候选；当前施工顺序以 [开发路线](开发路线.md) 和 [技术决策 Agent 方向收敛与实施路线](设计决策/技术决策Agent方向收敛与实施路线_2026-10-12.md) 为准。

## 使用规则

- 条目进入本文不代表已批准或已排期；
- 只有写入开发路线的工作才可以开始实现；
- 需要改变 Permission、Tool effect、Session、调度或恢复语义的候选，先单独形成设计决定；
- 已退场的 Plan、Workspace、Managed Run、学习领域和旧 M1/M1.5 候选保留在 [历史归档](历史归档/README.md)。

## 技术决策 Agent 后续候选

| 候选 | 进入条件 |
|---|---|
| 自动 Role / Skill 路由 | 显式选择的 A2/A3 已稳定，且真实技术决策 case 证明人工选择成为覆盖瓶颈 |
| 更多技术决策 Role | 第一个 Role 不能覆盖明确、重复出现的分析视角时 |
| 更多 Skill | 有可复现任务方法，且能定义输入、输出、证据和失败边界时 |
| MCP 增量服务 | 当前资料服务无法满足明确的决策信息缺口时 |
| 公开架构 benchmark | 已形成稳定、可审查的技术决策质量维度时 |
| 小规模私有 technical decision cases | 公开题不能覆盖真实约束组合时；不得修改冻结 Runtime case 的 expected |

## 暂缓候选

| 候选 | 暂缓原因 |
|---|---|
| Memory / Vector DB / RAG | 当前没有技术选型场景的失败证据证明它是前置能力 |
| Goal / Long Task 深度恢复和重规划 | 已冻结，除非新能力确实无法在现有边界内实现 |
| 多 Agent / Agent Team | 当前还没有单 Agent、Role、Skill 与 MCP 协作的失败证据 |
| Skill 市场与自动发布 | 先验证一个内置 Skill 的完整安全和评测闭环 |
| MCP sampling 或远端编排 | 会形成第二套执行系统，违背当前 Runtime 边界 |

新增候选时，记录触发它的真实任务、失败证据、预期收益和不做的代价；不要只因“能力看起来通用”而排期。
